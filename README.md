# AMLGuard — выявление подозрительных финансовых операций

Выпускной проект AI Academy KG, направление Data Science.
Автор: Nurislan Kablanbekov.

## Задача

Банки обязаны сообщать о подозрительных операциях в службу финансовой разведки, но отмывание денег — это около 0,1% среди миллионов переводов. Проверить всё вручную невозможно, а простые правила («крупная сумма», «наличные») дают много ложных тревог и не видят схем, в которых каждая операция по отдельности выглядит обычной.

Цель проекта — модель машинного обучения, которая ранжирует операции по риску отмывания, чтобы контролёр в первую очередь проверял самые подозрительные. Это цифровой инструмент финансового контроля: переход от выборочной проверки к риск-ориентированной.

## Результат

**Проверяя 1% самых рискованных операций, модель находит 75% всех случаев отмывания** за тестовый период. Правило-baseline при том же объёме проверки находит 2%, случайная проверка — около 1%.

| Модель | PR-AUC | Recall@1% | Precision | Recall | ROC-AUC |
|---|---|---|---|---|---|
| Правило-baseline (крупная сумма или наличные / биткоин) | 0,002 | 2% | 0,002 | 0,61 | 0,71 |
| Логистическая регрессия | 0,032 | 26% | 0,04 | 0,70 | 0,97 |
| Градиентный бустинг (по умолчанию) | 0,349 | 74% | 0,39 | 0,38 | 0,99 |
| **Градиентный бустинг (подобран)** | **0,385** | **75%** | **0,43** | **0,39** | **0,98** |

Тест: последние 15% операций по времени (594 678 операций, 793 случая отмывания). Подробности и графики — в [reports/results.md](reports/results.md).

## Данные

Открытый датасет [IBM Transactions for Anti-Money Laundering](https://www.kaggle.com/datasets/ealtman2019/ibm-transactions-for-anti-money-laundering-aml) (Kaggle), файл `HI-Small_Trans.csv`:

- 5,08 млн банковских операций: время, банк и счёт отправителя и получателя, сумма и валюта, способ оплаты, метка «отмывание»;
- данные синтетические: реальные банковские операции закрыты банковской тайной, поэтому для исследований по AML используют смоделированные финансовые системы;
- **найденная аномалия:** после основного периода (1–10 сентября 2022) в файле идёт «хвост» 11–18 сентября — около 1 100 операций, из них около 60% отмывания. Это артефакт генератора, который завершает начатые схемы; он целиком попал бы в тест и завысил метрики, поэтому исключён. В анализе: 5 077 228 операций, 4 522 случая отмывания (0,09%).

## Метод

1. **Очистка:** дубликаты, нулевые суммы, перевод сумм в USD по курсам, рассчитанным из самих данных.
2. **EDA:** дисбаланс классов, способы оплаты (отмывание сосредоточено в переводах ACH), валюты, суммы, время суток, закон Бенфорда.
3. **Признаки поведения счёта:** операции и суммы отправителя за 24 ч, входящие у получателя, время с прошлой операции, число уникальных получателей, первый ли перевод паре счетов, был ли обратный перевод.
4. **Защита от утечки:** история считается строго по прошлым операциям; автоматический тест сравнивает признаки на усечённых и полных данных.
5. **Разбиение по времени:** первые 24 ч — только история; затем 70% train, 15% validation, 15% test; андерсэмплинг обычных операций в train до 1:50.
6. **Модели:** правило-baseline, логистическая регрессия, градиентный бустинг (HistGradientBoosting); подбор гиперпараметров RandomizedSearchCV + TimeSeriesSplit по PR-AUC.

Главные факторы риска: способ оплаты, первый перевод новому контрагенту, сумма операции, число уникальных получателей у отправителя.

## Структура

```
notebooks/AMLGuard.ipynb   — весь анализ: данные, EDA, признаки, модели, результаты
src/features.py            — загрузка данных и расчёт признаков
src/explain.py             — объяснение риска отдельной операции
app.py                     — приложение Streamlit: очередь проверки, карточка операции
models/                    — обученная модель и метаданные (порог, метрики)
data/demo_transactions.csv — небольшой файл для демо
reports/                   — итоговые выводы и графики
```

## Как запустить

```bash
git clone https://github.com/<ваш-логин>/amlguard.git
cd amlguard
python -m venv .venv
.venv\Scripts\activate          # Windows;  macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt

# демо-приложение (работает сразу, на demo_transactions.csv)
streamlit run app.py

# полный анализ: скачайте HI-Small_Trans.csv с Kaggle в папку data/ и запустите
jupyter notebook notebooks/AMLGuard.ipynb
```

## Ограничения и развитие

Данные синтетические, около 10 дней; результаты нельзя напрямую переносить на реальный банк без дообучения на его операциях. Развитие: графовые признаки (цепочки через несколько счетов), проверка на более крупном наборе HI-Medium, разбор ошибок по схемам отмывания из `HI-Small_Patterns.txt`.
